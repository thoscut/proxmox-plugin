The number of minutes an agent can remain idle before being automatically terminated.

An agent is considered idle when it is online but not executing any builds.

Purpose: Automatically clean up unused agents to save resources and reduce costs.

Recommended Values:

  • 10-15 minutes: For frequently used agents, quick cleanup
  • 30 minutes (default): Balanced approach for most use cases
  • 60 minutes: For agents with expensive startup times
  • 0 minutes: Agent is terminated immediately after completing a build

Considerations:

  • Longer idle times reduce agent startup overhead for subsequent builds
  • Shorter idle times save resources but increase provisioning frequency
  • Consider your VM startup time when choosing this value
  • Balance between resource efficiency and build queue wait times

Note: This works in conjunction with the retention strategy. The default "Cloud retention strategy" respects this idle time setting.
