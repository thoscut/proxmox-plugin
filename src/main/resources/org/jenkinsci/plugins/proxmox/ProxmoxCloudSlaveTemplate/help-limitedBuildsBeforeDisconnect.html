Limited Builds Before Disconnect

Maximum number of builds this agent will execute before automatically disconnecting. After disconnection, the agent can be restarted for another cycle of builds.

Use cases:

  • 0 (default): Unlimited builds - agent runs indefinitely
  • 1: Single-use agent - disconnects after one build (good for isolation)
  • 5-10: Limited reuse - prevents agent drift over multiple builds
  • 20+: High reuse - balances efficiency with freshness

Benefits of limited builds:

  • Prevents environment drift from accumulating across builds
  • Ensures periodic VM cleanup via snapshot revert
  • Reduces risk of side effects between builds
  • Balances between clean environments and resource efficiency

Recommendation: For critical builds requiring pristine environments, use a low value (1-5). For routine builds where efficiency matters more, use higher values (20+) or 0 for unlimited.

Note: Works in combination with snapshot revert policies. When the agent disconnects after reaching the limit, it can be reverted to a clean snapshot before the next cycle.
