Retention Strategy

Controls when and how Jenkins keeps the agent online or takes it offline. This determines the lifecycle behavior of your Proxmox VM agents.

Available retention strategies:

  • Keep this agent online as much as possible:
    • Agent stays online continuously
    • VM keeps running after builds complete
    • Good for: Permanent agents, high-frequency builds
    • Resource usage: High (VM always running)
  • Take this agent online when in demand, and offline when idle:
    • Agent goes offline after configured idle period
    • Can be combined with "Max Idle Minutes" setting
    • Good for: On-demand agents, cost optimization
    • Resource usage: Medium (VM runs only when needed)
  • Take this agent online according to a schedule:
    • Agent comes online at specific times
    • Good for: Batch jobs, scheduled builds
    • Resource usage: Low (VM runs on schedule only)

Proxmox-specific considerations:

  • Snapshot revert: When agent disconnects, snapshot revert policy can restore clean state
  • Instance cap: Retention strategy affects how many VMs are kept running
  • Max idle minutes: Works with retention strategy to control VM lifecycle
  • Cost optimization: Use demand-based retention to minimize resource usage

Recommendation: For cloud-provisioned Proxmox VMs, use "Take this agent online when in demand, and offline when idle" with appropriate "Max Idle Minutes" setting. This balances responsiveness with resource efficiency and allows snapshot revert to maintain clean environments.
